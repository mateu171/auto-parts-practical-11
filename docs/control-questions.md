# Контрольні питання — Практична №11

1. **Unit / Integration / E2E.** Unit-тест перевіряє один метод/клас повністю ізольовано (залежності замінені mock-ами) — швидкий, точково локалізує помилку. Integration — перевіряє взаємодію кількох реальних компонентів (наприклад, сервіс + реальна БД). E2E — проходить увесь шлях запиту (HTTP → pipes → guards → controller → service → відповідь), як це робить клієнт; найповільніший, але найближчий до реальності.
2. **Навіщо mocking.** Щоб ізолювати тестований код від БД, мережі, пошти та інших модулів: тести стають швидкими, детермінованими, а помилки — локалізованими; також можна змоделювати рідкісні сценарії (запис не знайдено, збій SMTP).
3. **`Test.createTestingModule()` та `getRepositoryToken()`.** `createTestingModule` створює мінімальний DI-модуль лише з потрібними провайдерами. `getRepositoryToken(Entity)` повертає DI-токен, під яким TypeORM реєструє репозиторій сутності; за цим токеном підставляється mock (`{ provide: getRepositoryToken(AutoPartEntity), useValue: mockRepo }`).
4. **AAA.** *Arrange* — підготовка даних і mock-ів; *Act* — виклик тестованого методу; *Assert* — перевірка результату та побічних ефектів (`expect`).
5. **Supertest без порту.** `request(app.getHttpServer())` отримує внутрішній Node HTTP-сервер і сам прив'язує його до тимчасового ефемерного порту на час запиту, тому окремо `app.listen()` не потрібен.
6. **Code coverage.** Частка коду, виконана тестами. *Statements* — інструкції; *Branches* — гілки `if/else`, `?:`, `&&`; *Functions* — викликані функції; *Lines* — рядки. Високе покриття не гарантує якість тестів, але низьке показує непротестований код.
7. **OpenAPI та Swagger UI.** OpenAPI — стандартна машиночитана специфікація REST API (JSON/YAML). Автогенерація дає актуальну документацію без ручної підтримки, інтерактивне тестування запитів у браузері, експорт `/api/docs-json` для генерації клієнтів і Postman.
8. **Декоратори `@nestjs/swagger`.** DTO: `@ApiProperty`, `@ApiPropertyOptional`. Контролери: `@ApiTags`, `@ApiOperation`, `@ApiResponse`, `@ApiParam`, `@ApiQuery`, `@ApiBearerAuth`.
9. **Multi-stage build.** Збірка (devDependencies, компілятор, вихідний код) відбувається в окремому етапі, у фінальний образ потрапляють лише `dist` та production-залежності: образ менший, швидше завантажується, має меншу поверхню атаки й не містить вихідного коду та інструментів збірки.
